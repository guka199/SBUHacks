1. PROJECT OVERVIEW

ViralPilot is a video planning studio for creators. It helps compare a video's
content readiness across TikTok, Instagram Reels, YouTube Shorts and YouTube
long-form, inspect timestamped observations, and improve publishing copy.
Scores are estimates for creative decisions, not promises of virality.

The homepage starts in a peaceful, real-time creator workspace. Detailed
illustrative analytics tools accumulate INSIDE the monitor. A fixed pool of
notifications creates overload. Glass panels deform and converge, the chaos
contracts, ViralPilot appears, and the camera enters the actual interactive
studio. Scrolling upward reverses the same timeline.

The main app flow is studio -> upload -> processing -> report -> video insights
or content optimizer. Demo data is clearly labeled. No login is required.

- Next.js 16 App Router, React 19, TypeScript.
- Tailwind v4 base processing and custom CSS; no component-suite dependency.
- Three.js, React Three Fiber, Drei, GLB/glTF, PBR textures and local HDRI.

- Zod schemas validate live API responses and shared TypeScript types.

UI UX Pro Max was installed with npm install -g ui-ux-pro-max-cli, initialized
with uipro init --ai codex, read, and used for accessible controls, readable
charts, responsive layout, reduced motion, Three.js and scroll guidance.
The user's pinned natural palette overrides its generic dark/violet suggestion.
Applied guidance is recorded in design-system/viralpilot/MASTER.md and DNA.json. Taste and
Impeccable guidance were also used. Three.js Skills, official GSAP Skills,
Design DNA, LottieFiles Motion Design and Genjutsu (official website installer)
were installed, read and applied. Fiber is a compatible library, not a skill.
Concrete applications are listed in MASTER.md. Skill tooling is not committed.

5. HOW TO RUN

Prerequisites: Node.js 22+, npm and a modern browser. WebGL2 enables the desktop
room; the frontend also works through a static room fallback.

From this branch's repository root:
  npm ci
  npm run dev
Open http://localhost:3000.

Checks: npm run check
Production: npm run build, then npm start

No environment file is needed for demo mode. To configure, copy .env.example
to .env.local (ignored):
  NEXT_PUBLIC_DEMO_MODE=true
  NEXT_PUBLIC_API_MODE=demo
  NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
  NEXT_PUBLIC_ENABLE_3D=true

Set NEXT_PUBLIC_DEMO_MODE=false for live requests. This setting takes precedence
over the legacy NEXT_PUBLIC_API_MODE. Set NEXT_PUBLIC_ENABLE_3D=false to disable WebGL.
NEXT_PUBLIC values are compiled into browser bundles: restart development or
rebuild after changing them. NEVER put secrets or private API keys in them.

6. BACKEND INTEGRATION GUIDE

All live requests are in src/lib/api.ts. Components do not scatter fetch calls.
Upload uses analysisApi.create, then waitForAnalysis. Dashboard direct links
use analysisApi.get and polling. Optimizer uses analysisApi.rewrite.

Default demo mode is deliberate. Live errors are shown and never silently
replaced by successful-looking demo results.

IMPORTANT EXISTING BACKEND DIFFERENCE
The fetched main branch (6f2e4cf, October 24) currently exposes POST /score, requiring caption,
comma-separated platforms, context and optional file, with a 200 MB upload
limit. This frontend expects asynchronous /api/analyses jobs, four format IDs,
and timestamped video feedback; it accepts 250 MB locally. Changing API_BASE
alone does not integrate these interfaces. Agree on one contract, adapt the
backend or src/lib/api.ts, align upload limits, and map YouTube short/long
formats deliberately. Do not invent missing hook/timestamp scores from a
backend response or mislabel model-only fallback as complete AI analysis.
No teammate backend files were overwritten or merged.

Expected browser API contract:
A. POST /api/analyses
Content-Type: multipart/form-data (the browser supplies the boundary).
Fields:
  video: the original File bytes and filename
  platforms: a JSON string, e.g. ["tiktok","instagram","shorts","youtube"]
XHR reports actual upload progress. Upload timeout: 120 seconds.
Example initial response:
{
  "id": "job_42",
  "status": "queued",
  "progress": 0,
  "stage": "Waiting for analysis"
}

B. GET /api/analyses/job_42
Polls approximately every two seconds, maximum 150 polls. IDs are URL encoded.
Example intermediate response:
{
  "id": "job_42",
  "status": "processing",
  "progress": 60,
  "stage": "Comparing platform suitability"
}

Example complete response (one selected platform; return all selected platforms
using the same shape). Every field below matches the actual Zod schema:
{
  "id": "job_42",
  "status": "complete",
  "progress": 100,
  "stage": "Ready",
  "result": {
    "id": "job_42",
    "mode": "live",
    "video": {
      "name": "my-video.mp4",
      "durationSeconds": 24,
      "width": 720,
      "height": 1280
    },
    "summary": "The opening is clear; shorten the pause before the payoff.",
    "platforms": [{
      "id": "tiktok",
      "score": 86,
      "hook": 91,
      "pacing": 82,
      "format": 94,
      "assessment": "A strong short-form opening with a clear visual payoff.",
      "opportunities": ["Trim the pause at 0:08.", "Add readable captions."],
      "suggestions": {
        "hook": "You do not need a perfect idea. Start with this.",
        "title": "Make something before you feel ready",
        "caption": "Less overthinking. More making. #CreativeProcess",
        "description": "A short experiment in turning an idea into a story.",
        "cta": "What would you make? Tell me below.",
        "edits": ["Show the finished result first.", "Trim the pause at 0:08."]
      }
    }],
    "observations": [{
      "id": "pace-1",
      "time": 8,
      "end": 10,
      "kind": "opportunity",
      "title": "Tighten this pause",
      "detail": "The story stops advancing here. Cut to the next action."
    }]
  }
}

A failed job is:
{"id":"job_42","status":"failed","progress":60,"stage":"Failed",
 "error":"This video's codec is unsupported. Export H.264 and try again."}
Non-2xx responses also surface errors. A completed job MUST include result.
Scores must be 0-100; platform IDs must be unique; observation timestamps must
fit within the actual positive video duration. Live mode requires mode="live".

C. POST /api/analyses/job_42/rewrite
Content-Type: application/json
Request:
{"platform":"tiktok","tone":"playful"}
Supported tones: direct, playful, educational.
Response:
{
  "suggestions": {
    "hook": "Your next good idea is hiding in plain sight.",
    "title": "Make something before you feel ready",
    "caption": "One small idea. A little less overthinking. #MakeSomething",
    "description": "A short experiment in making a story your own.",
    "cta": "What will you start today?",
    "edits": ["Open on the result.", "Trim the first pause."]
  }
}
The response updates the selected platform, remains available when switching
report tabs and is included in export. Changing tone alone does not call the
server; the user presses Regenerate (or Try sample tone in demo mode).

TypeScript source of truth: src/lib/contracts.ts.
  PlatformId = "tiktok" | "instagram" | "shorts" | "youtube"
  AnalysisJob = {id, status, progress, stage, result?, error?}
  AnalysisResult = {id, mode, video, summary, platforms, observations}
  PlatformResult = {id, score, hook, pacing, format, assessment,
                    opportunities, suggestions}
  Suggestions = {hook, title, caption, description, cta, edits:string[]}
  VideoMetadata = {name, durationSeconds, width, height}
  RewriteRequest = {platform:PlatformId, tone:"direct"|"playful"|"educational"}
Most are inferred directly from Zod; extend the schema first, then UI consumers.

Video handling: readVideo creates a temporary object URL for metadata. Session
creates another URL for local previews and revokes it on replacement/unmount.
No base64 conversion, localStorage video, or persistent file database is used.
Only live Analyze sends the actual File. Cancel aborts XHR/polling but does not
currently delete/cancel a job already accepted by the server. Add a backend
cancel endpoint if server-side cancellation is required.

Results display: setResult feeds Dashboard. Platform IDs select cards, meters,
comparison bars and optimizer copy. Observations drive player seek positions.
After refresh, local previews are gone. Live /analysis/[id] retrieves a report,
but there is no remote video URL in this contract, so a restored report shows a
clear unavailable-preview state. Add a signed playback URL if required.

CORS: allow the actual frontend origin (localhost:3000 in development) and the
required POST/GET methods. No authentication headers are implemented. For
production, add a same-origin server proxy or a deliberate authentication
contract; keep AI-provider keys on the backend. Validate file content and size
server-side too. No fixture data should be used to conceal a backend failure.

7. THREE.JS AND ANIMATION SYSTEM

WorkspaceScene is lazy-loaded on desktop >=900px with WebGL2 and no reduced-
motion preference. React 19 uses Fiber 9, Drei 10 and Three 0.180. The Canvas
caps DPR at 1.5, uses AgX tone mapping, a local 1K HDRI and properly initialized
rectangular window lighting. Directional light uses a 2048 shadow map; two
single-frame contact-shadow captures ground the furniture and desk objects.
CinematicPost uses a half-float render target, 4x MSAA, a restrained vignette
and OutputPass. It does not add bloom, chromatic aberration or depth-of-field
that would interfere with screen readability. Rendering suspends offscreen.

ProfessionalHardware loads actual licensed GLBs: Innerscene monitor/mouse
(CC0), Amazon.com Rivet desk (CC BY 4.0), AndreiVNK headphones (CC BY 4.0),
and liweihang's sculpted keyboard case/keycaps (MIT). The keyboard shares key
geometry across 68 keys and has an original legend atlas. Poly Haven plants,
articulated lamp, oak PBR maps and HDRI remain CC0. Original architecture and
accessories complement the licensed hardware. Fabric gets a procedural weave
bump and physical sheen. Sources, authors, hashes and changes are recorded in
ASSET_NOTICES.md, public/assets/*/sources.json, license notices and /credits.
Retain attribution for desk/headphones in derivatives and scene captures.

All GLBs use Meshopt compression. Suitable textures become WebP <=1024px;
normal maps and runtime oak UVs are preserved. Hardware compression reduces
monitor 84KB to 27KB, desk 2.17MB to 1.39MB, keyboard 5.64MB to 1.17MB,
headphones 1.15MB to 608KB and mouse 2.57MB to 370KB (decimal rounded sizes).
The committed optimization manifest records exact byte counts.

ScrollExperience owns one scoped GSAP context/ScrollTrigger. Choreography is
in home/choreography.ts, with a deterministic 100-unit playhead:
  0-17  peaceful room; early camera approach begins at 2
  17-31 detailed YouTube opens, settles; retention graph draws and metrics reveal
  31-47 Instagram then TikTok open, charts grow and windows rearrange
  44-70 12 bounded notifications, five windows and seven browser tabs accumulate
  69-78 windows become translucent, their content softens and motion slows
  74-87 asymmetric radii, skew, stretch and convergence collect the windows;
        six separate glass panels follow curved approaches into a central lens
  79-89 SVG Bezier contour morphs from flowing to stretched to settled;
        a displaced/blurred local caustic adds refraction-like highlights
  84-92 Meet ViralPilot appears within the settled glass
  90-98 the actual interactive studio expands through a rounded inset clip
  92.5-100 the same projected DOM screen grows continuously to the viewport

Glass uses CSS backdrop blur and translucent surfaces, SVG outline highlights,
shape deformation and converging geometry; it is not just a crossfade. SVG
refraction affects only a local decorative caustic: applying URL backdrop
filters to the whole transformed DOM produced clipping in Chromium and was
removed. Essential text stays outside that distortion. No Lottie runtime is
required: LottieFiles principles (anticipation, staging, stagger, follow-through,
short overshoot/settle and reduced-motion alternatives) shape the GSAP motion.

No timers spawn analytics notifications. Scrubbing backward reconstructs each
stage from the same playhead. Chapter buttons target the same ScrollTrigger;
context cleanup removes pins/tweens on unmount or responsive changes. Global
CSS smooth scrolling is disabled because it competed with chapter positioning.

ScreenProjection uses the imported monitor's measured four screen vertices,
including its physical 5-degree tilt. projection.ts solves a CSS homography.
The same HTML interface remains aligned with the display while the camera
moves. Entry blends projected corners into viewport corners and changes the
layout from 960x540 to viewport size. Controls leave inert mode near completion.
No abrupt route change or static analytics screenshot substitutes for entry.
Update the corner coordinates if replacing the monitor asset or its pose.

Mobile/no-WebGL uses workspace-room-v3.jpg plus the same bounded HTML story.
Reduced motion removes the pin/zoom and exposes a normal studio beneath a still
hero. NEXT_PUBLIC_ENABLE_3D=false disables Canvas globally. Edit chapter stops
in lib/experience.ts, timeline in home/choreography.ts, glass shape/component
in LiquidGlass.tsx and appearance in experience.css. Preserve reversibility.

Optional asset rebuild: build:assets; fetch:assets; fetch:hardware;
build:keyboard; optimize:assets. Normal setup uses committed optimized assets.
fetch:hardware pins the keyboard source revision; its raw sources go in ignored
work/assets. Do not redistribute user reference files with the app.

8. DESIGN SYSTEM

Warm ivory #F7F3EA, forest ink #172D26, pale sky #D5E7EA and sage #95AB94.
White report surfaces and restrained oak/rose/cyan distinguish data without
turning the product into a different theme. Instrument Serif carries editorial
headings; DM Sans carries controls, metrics and reading copy. Fonts are local.
Glass is purposeful in the cinematic transformation and light navigation;
functional reports use solid backgrounds and explicit numeric labels.

Reusable controls: button variants, platform icons, CopyButton, native form
controls, keyboard-operable report tabs, shared brand mark and AnimatedLink.
Design tokens and applied skill recommendations: DESIGN.md and

careful desk objects; Crate supplies serif scale and a tangible 3D centerpiece;
Railroad supplies architectural framing of nature and continuous immersion.
